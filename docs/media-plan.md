# Screenshot and media plan

The initial public repository should use a small, deliberate set of real product visuals rather than a large screenshot gallery.

| Asset | Status | Purpose | Source size | README placement |

## Capture standards

- Use the English UI for primary public screenshots.
- Prefer the final packaged executable rather than a development IDE run.
- Keep CUDA/provider status visible where useful.
- Do not expose local usernames, OneDrive paths, IDEs, terminals, private diagnostics, or test-case identifiers.
- Use neutral demo filenames such as `video_analysis_demo.mp4` and `group_photo_demo.png`.
- Verify that the demo media and all visible faces may legally be shown in a public portfolio before publishing the screenshots.

## Optional demo video

A short 10–15 second screen recording can be added later if it materially improves the repository. It is not required for v1.0.0 and should not delay release.
